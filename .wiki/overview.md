# 项目概述

本项目是一个基于 TypeScript 构建的命令行工具，旨在通过大语言模型（LLM）自动为代码库生成高质量的项目文档、技术架构说明以及 Wiki 页面。它能够扫描源代码结构、解析函数类型，并结合 AI 智能生成，解决开发者在项目中手动撰写技术文档时效率低下、内容不完整的问题。

## 核心设计思路

项目的核心设计思路是将静态代码分析与 AI 内容生成能力深度结合。首先，它利用 Tree-sitter 语法解析器对 TypeScript 源代码进行精确分析，提取出代码中的模块结构、函数签名、类型定义等关键信息。然后，将这些结构化数据作为上下文，传递给 OpenAI 等 AI 模型，由模型生成自然语言描述的技术文档、架构说明或 Wiki 内容。这种方式既能保证文档与代码实际结构保持一致，又能利用 AI 的语义理解能力生成易懂的叙述。

工具采用了模块化的策略模式来支持不同的文档生成目标。例如，针对项目总览、后端架构、代理（Agent）逻辑等不同维度，定义了相应的策略类，每个策略负责特定的上下文提取和文档样式控制。此外，项目还内置了一个基于 SQLite 的本地存储系统，用于缓存已分析的代码数据和已生成的文档片段，以避免重复计算，提升多次运行时的效率。

在交互层面，工具通过 Commander.js 提供命令行接口，支持多种子命令，例如初始化配置、生成完整文档、更新特定部分等。工作流通常为：用户先通过命令扫描源代码目录，工具会分析代码并生成一个中间上下文文件；随后用户调用生成命令，工具将上下文发送给 AI 并输出最终文档。

## 技术栈

以下表格列出了项目所使用的主要技术及其在项目中的用途：

| 技术 | 用途 |
|------|------|
| TypeScript | 主要开发语言，提供类型安全和现代语法 |
| @ai-sdk/openai | 与 OpenAI API 交互，调用大语言模型生成文档内容 |
| ai | 底层 AI SDK，提供统一的模型调用抽象层 |
| better-sqlite3 | 本地数据持久化，缓存代码分析结果和已生成文档 |
| commander | 命令行界面框架，定义子命令和参数解析 |
| tree-sitter-typescript | 语法解析器，用于提取 TypeScript 代码的结构和类型信息 |
| web-tree-sitter | Tree-sitter 的 WebAssembly 绑定，支持在 Node.js 环境中运行 |
| tsup | 打包工具，将 TypeScript 源码编译为可发布的 CLI 程序 |
| vitest | 单元测试框架，用于测试核心逻辑和命令处理 |

## 项目结构

项目的源代码主要位于 `src` 目录下，其组织方式如下：

- **`src/cli/`**：包含命令行接口的实现，包括命令注册、参数处理和命令处理函数。其中 `index.ts` 是 CLI 的主入口，负责初始化环境并启动命令循环；`commands` 子目录下定义了各个子命令的具体逻辑。
- **`src/core/`**：核心业务逻辑层，包括代码分析器（调用 Tree-sitter 解析源代码）、上下文提取器（将 AST 转换为结构化数据）、以及文档生成器（与 AI 模型交互并生成最终输出）。
- **`src/strategies/`**：实现了多种文档生成策略，如项目总览策略、后端架构策略、Wiki 策略等。每种策略都定义了如何从代码上下文生成特定类型的文档。
- **`src/storage/`**：封装了与 better-sqlite3 的交互，提供缓存数据的读写接口。
- **`src/utils/`**：包含通用工具函数，如文件读写、路径处理、模板渲染等。
- **`tests/`**：存放单元测试和集成测试用例，其中 `fixtures` 目录下包含用于测试的样本项目。

## 入口文件

以下是项目的主要入口点及其作用：

- **`src/cli/index.ts`**：CLI 工具的主入口点。它初始化 Commander 应用，注册所有子命令，设置全局选项（如输出目录、日志级别等），并启动命令行处理循环。用户直接运行此文件或编译后的二进制文件即可使用工具。
- **`src/cli/commands/index.ts`**：子命令的集中注册页面。它导入了所有独立命令（如 `scan`、`generate`、`init` 等），并将它们添加到 Commander 的父命令中。此文件负责命令的组织和路由。
- **`tests/fixtures/sample-project/src/index.ts`**：测试样本项目的主文件。这是一个用于集成测试的示例 TypeScript 项目入口，工具会针对它运行分析，验证文档生成是否正确。它不是生产代码，而是测试基础设施的一部分。
